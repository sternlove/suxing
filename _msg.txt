fix(skill): 技能任务强制走云端，绕开 1.7B 的指令理解缺陷

实测结论：1.7B 无法可靠执行技能指令。
  system 里放「现在请立刻执行【翻译】技能」+ user 里放「按翻译的要求处理…」，
  三轮测试全部回「先生，今天天气不错。」，第三轮还「没答上来」。
  这不是 prompt 措辞问题，是模型能力边界。

改法：按任务类型分流，不是降级
  闲聊      → 本地 1.7B（省流量、断网可用）
  技能任务  → 强制云端（有 Key 且在线时），断网自然落回本地

实现：send() 的路由判断之前先 match 文档技能，命中且云端可用就直接 runCloud，
      把 buildBlock 的输出（含技能要求 + 要处理的内容）当 user 消息。

踩坑：第一次把 await 插进了同步方法 buildChatMl，编译报 await 只能在 async 里用。
      分流必须放在 async 的 send() 里，且不能依赖 buildChatMl 的局部变量。
